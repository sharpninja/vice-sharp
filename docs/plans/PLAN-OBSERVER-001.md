## 1. Mechanism (decision-complete)

1. Build target: the separate materialization `artifacts/immutable-vice/cc67418c.../source` on each host (byte-identical on both, `docs/receipts/native-vice/20261019T202542-linux-materialization/`), stock objects linked with external translation units only; `native/vice` untouched; every generated file inventoried and outside both trees.
2. Fast path withheld: `ld --wrap=mem_mmu_translate`. `__wrap_mem_mmu_translate` calls `__real_mem_mmu_translate` and then sets `*limit = 0` (and `*base = NULL`), so `JUMP` (`maincpu.c` 83 to 89) and `maincpu_resync_limits` (519 to 524) leave `bank_limit` 0 and every `FETCH_OPCODE` and `FETCH_PARAM` takes the `LOAD` branch (`vic20cpu.c` 125 to 134; `6510core.c` 2081 to 2107, 537 to 541). Emulated semantics unchanged by design; proven, not assumed (section 3).
3. Access capture (corrected 20:48 after LEGION2's review; the first draft said "point the pointers at wrapper-owned tables and wrap `mem_toggle_watchpoints`", which fails because the pointers are reassigned by intra-object calls that `--wrap` never sees: `vic20mem.c` line 523 calls `mem_toggle_watchpoints` from inside `vic20mem.c`, and on x64sc the static helper `mem_update_tab_ptrs` (`c64memsc.c` 166 to 186) re-points all four pointers on every `mem_pla_config_changed` (226 to 243), that is on every banking change). Corrected mechanism: the wrapper patches the contents of VICE's own tables, not the pointers, so every reassignment still lands on patched tables. After `mem_initialize_memory` (and `cartridge_init_config` and the internal expansions, `c64memsc.c` 917 to 924) the wrapper reads the current row through `_mem_read_tab_ptr` and `_mem_write_tab_ptr`, saves each original entry, and writes a trampoline per page into the row in place; on x64sc the 32 rows of the static `mem_read_tab[NUM_CONFIGS][0x101]` and `mem_write_tab` (110 to 111) are reached from the current row pointer and `mem_get_current_bank_config()` (222, global) by the array layout, verified at init by a self-test (`mem_read_tab_set(config, page, f)` (751, global) followed by a read of the computed address must yield `f`, else fail closed); the watch tables (`mem_read_tab_watch`, `_mem_read_tab_watch`) are reached by calling the global `mem_toggle_watchpoints(1, NULL)`, patching the row the pointer then shows, and toggling back. Each trampoline records `kind` (read, write, dummy read, dummy write by which pointer it is reached through, decided by comparing the live pointers at entry), `address`, the data byte (the original read's return value, or the stored value) and `maincpu_clk`, then calls the saved original. Table contents rewritten by VICE after the patch are the central hazard, and the per-cycle rescan is the only coverage guarantee (LEGION2 review 20:49, accepted): the writers are called from inside their own objects too (`c64memsc.c` 800, 806 and 829 call `mem_set_write_hook`, 855 to 862 call `mem_read_tab_set`; `vic20mem.c` 396 to 462 call `vic20_mem_enable_ram_block` and `vic20_mem_disable_ram_block` from the RAM-block paths that also run at runtime when an expansion resource is toggled), and `c64memsc.c` 644 to 667 writes `mem_read_tab[i][j]` and `mem_write_tab[i][j]` directly for the 256K expansion segments, which no function wrap can reach. `--wrap` on the four global writers (`vic20_mem_enable_ram_block` and `vic20_mem_disable_ram_block`, type T in `vic20mem.o`; `mem_read_tab_set` and `mem_set_write_hook`, type T in `c64memsc.o`, cross-object callers `c64meminit.o` and the other machines' meminit objects) is therefore only a fast re-patch for some paths. The guarantee: in the wrapped per-cycle hook, the wrapper rescans the rows the four live pointers resolve to (read, write, dummy read, dummy write; at most four rows of 0x101 entries) and re-patches, counting every entry found unpatched as a fail-closed `Missing` for that cycle, never a silent gap. A row rewritten while not current is covered by the same rescan because a row becomes current only through a pointer reassignment that precedes the next access by at least one hook, which is exactly what the ordering proof must establish for every path: banking (`mem_pla_config_changed`), the resource setters (`vic20mem.c` 396 to 462), the 256K paths (`c64memsc.c` 644 to 667), cartridge configuration and the watchpoint toggle; where a rewrite can precede an access inside the same cycle, that access is a fail-closed `Missing`, and if the proof shows it can happen on a workload the lockstep needs, that is a named blocker. The S0 audit lists every assignment site of the four pointers and every writer of the table contents per machine (direct array writes included), classified as cross-object (wrappable) or intra-object (rescan only), with the thread on which each runs.
4. Half-cycle and phase: the per-cycle hook (`__wrap_vic_cycle` for xvic; the `vicii_cycle` equivalent for x64sc, named by the nm probe) advances the half-cycle index and emits the `VICE_OBS` line of the step 1 contract once per CPU cycle with the accesses captured since the previous hook, PHI1 for the dummy-read-only or idle half and PHI2 for the access half as VICE's single-cycle model exposes them; where VICE performs no access in a cycle the kind is `idle` and `data` is what the contract requires on idle half-cycles (the step 1 self-assessment's open item, resolved by evidence in S3: either the last bus value VICE exposes or a fail-closed `Missing:Data`, never an invented value).
5. Interrupt mask and stolen cycles: `maincpu_int_status->global_pending_int` (reachable global per the nm probe) for `interruptMask`; `stolen` from `maincpu_ba_low_flags` and `vicii_steal_cycles` on x64sc; on the VIC-20 `ba` and `stolen` follow Payton's Ba/Aec applicability ruling (constant 0 only if he rules "not applicable", with the contract amended to say so; otherwise `Missing:Ba` fail closed).
6. Output: `VICE_OBS` lines on stdout in binary mode on Windows (CRLF is a framing fault), through the retained stdio adapter path only after its retention contract is fixed (F-04), otherwise through a dedicated file descriptor opened by the wrapper so native stdout is not involved; decided in S2 by the F-04 state.
7. Pause and resume: the existing clock gate (`tools/immutable-vice/clock-gate.c`) stays the permission mechanism; the observation line precedes the gate's `VICE_GATE` record for the same cycle, so the host reads the record before permitting the next cycle (deterministic per-cycle pause and resume replacing `-limitcycles`).
