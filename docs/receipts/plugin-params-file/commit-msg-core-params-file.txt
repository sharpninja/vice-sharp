fix(plugin-core): pass repl-invoke params through a file, never the child command line

On Windows a child command line is limited to 32,767 characters. Invoke-McpPlugin.ps1
passed the whole params YAML to repl-invoke.ps1 as -ParamsYaml, so a 194 KB
workflow.requirements.updateBatch failed with "The filename or extension is too long"
(triage-report-821fe2da58284b4ea21604cb2da2fccb). Linux allows about 2 MB, which hid it.

- New lib-ps/repl-params-transfer.ps1: New-McpReplParamsTransfer writes a private
  UTF-8 (no BOM) temporary file and returns -ParamsPath arguments (none for empty
  params); Remove-McpReplParamsTransfer deletes it; Read-McpReplParamsFile reads it.
- repl-invoke.ps1 accepts -ParamsPath (exclusive with -ParamsYaml; a missing file
  fails). -ParamsYaml stays for in-process callers.
- Invoke-McpPlugin.ps1 and plugin-hook.ps1 (OpenSession launch) pass -ParamsPath and
  remove the file in finally. The REPL hop already uses stdin.
- cache-manager.ps1: replayed params drop the serializer's trailing line break, so a
  replay sends the params text as written (TEST-MCP-PLUGIN-PSONLY-001).

before the helper existed; binding 8/8, including the wrapper carrying a 200 KB payload
