## Design decisions recorded in the wrapper header (observation from the materialized source, cited there)

- Rows to patch are the ones the dummy pointers resolve to right after the rebuild: nowatch rows for watch flags 0 and 1, watch rows for flag 2; in each case an access ends in exactly one trampoline, because the watch functions delegate to the nowatch rows (`vic20mem.c` 274 to 284). A real pointer on a delegating watch row is reported as `foreign` every cycle, which is honest: the monitor is not part of a gated run.
- The kind of an access through the real rows is decided by whether the dummy pointer still points at the wrapper's dummy row; if VICE has re-pointed it (intra-object, every x64sc banking change), the kind is reported `missing` until the next hook re-points it. Inference, to be measured in S3 and S4: on x64sc this affects at most the accesses between a `$01` write and the next cycle hook.
- `translate` emits one event per call; the production sink decides what to keep. The per-access sink call is immediate; the `VICE_OBS` line composition per half-cycle belongs to the S2 adapter.
